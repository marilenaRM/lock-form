Stop overwriting each other’s edits.

Alice opens a record, Bob saves it, Alice saves her stale copy and Bob’s change is gone without anyone noticing. This bundle catches it when the form is submitted, the way CSRF protection works: it adds a hidden token to every root form, without touching your form types or depending on Doctrine.

$composer require lock-form/form-concurrency:dev-main

Prototype, not on Packagist yet: add the GitHub repository first (see Install).

The lost update

Whoever saves last
wins, silently.

It started with our dashboard’s edit forms. Alice and Bob open the same record a few minutes apart, Bob saves first, and when Alice saves the old version she still has on screen, his change is gone and nobody is told. Nothing slow or racy is involved here: the window that matters is the time a person spends on the form, which is minutes rather than milliseconds.

The bundle takes a fingerprint of what the form displays when it is rendered, sends it in a hidden field, and compares it with what is stored when the form comes back. If they differ, the form is invalid: the user keeps what they typed, sees which fields moved and what they hold now, and has to tick a box to save anyway.

Automatic

Like CSRF, nothing to wire

Once the bundle is enabled, every root form is protected and your form types stay as they are. GET forms (searches, filters) are left alone.

Storage-agnostic

Entities, DTOs, arrays

It hashes the view data of each field rather than your object, so you don’t need a version column, a migration or Doctrine.

Field-level

Says what changed

Each field that moved gets an error with its current value. A change the user couldn’t overwrite anyway (a field outside the form, a disabled one) is not a conflict.

How it works

Hash what the form shows, at the right moment.

The fingerprint covers what each editable field displays, after its own data transformers, rather than the object behind it. By then dates are formatted, a related entity is down to its id and an enum to its scalar, so two loads of the same state always give the same fingerprint.

One edit, two requests 
GET  /article/42/edit
  find(42) → createForm($article)
  POST_SET_DATA (root, after the fields are filled)
    F1 = fingerprint of what is displayed
  render <input hidden _concurrency_token=F1>

POST /article/42/edit
  find(42)  ← current state in storage
  PRE_SUBMIT (root, before the fields)
    F2 = fingerprint of what is stored now
    F1 = F2 ? accept : conflict, changed paths
  POST_SUBMIT
    drop the paths whose submitted value is already F2’s
    none left ? accept : global error + one error per field left
The token 
// base64url(JSON), one entry per editable leaf field
{
  "name":         "3f9a…",
  "price":        "b07c…",
  "author.email": "91de…",
  "tags.1":       "e44b…"
}
// truncated HMAC-SHA256 keyed with kernel.secret

Keeping the paths is what lets the form say which fields changed. The key doesn’t prevent tampering; its job is to stop anyone from brute-forcing a value the form never shows, such as a PasswordType (the code review of the prototype caught that one).

The acknowledgement box carries the token of the state the user was shown. Sending the same form again is still a conflict, and if someone saves in between, a new conflict comes with a new box.

A user who types in the value a field holds now overwrites nothing, so that field is no longer a conflict, and the save goes through if no other field is. The submitted values are put back through each field’s own transformers before the comparison, so 15 matches 15.00.

EventPriorityWhy
POST_SET_DATA-1024After the form’s own listeners, so fields they add are included.
PRE_SUBMIT1024Before the form’s own listeners, which may rebuild fields from the submitted values.
POST_SUBMIT0A field clears its errors on submit, so field errors can only be attached afterwards.

    Why this approach

    We looked at four options first.

    Each one is summed up below; the full reasoning, and the tests that back it, are in the design notes.

    Rejected

    A. Lock the record while it’s open

    Over HTTP a lock that lasts as long as someone thinks needs a TTL, a heartbeat and a “take over” button, and once it expires the overwrite goes through anyway. Useful later as a non-blocking “Bob is editing” hint.

    Complement

    B. Doctrine #[ORM\Version]

    It is the only truly atomic option. But it is limited to Doctrine, needs a column per entity, raises false conflicts on fields the form doesn’t show, and the version still has to travel in the form.

    Rejected, tested

    C. Hash the object in PRE_SET_DATA

    The event fires before the fields are filled, and an object hash changes for the wrong reasons: properties outside the form, time zones, proxies, collections.

    Kept

    D. Fingerprint what the form displays

    View data of each editable field, taken after POST_SET_DATA and again in PRE_SUBMIT. Only what this user could change is compared.

    Know the limits

    It detects, it doesn’t guarantee.

    It protects users from each other’s mistakes, not from someone acting in bad faith.

    ✓ What it covers

    • Back-office edit forms where two people may open the same record minutes apart.
    • Entities, DTOs or arrays, embedded forms, collections and EntityType relations.
    • LiveComponent forms using ComponentWithFormTrait, as long as the record is a LiveProp.

    ✗ What it doesn’t

    • Two submissions in the same few milliseconds both pass the check. Add #[ORM\Version] where that matters.
    • An object kept in the session instead of reloaded on each request: nothing to compare against.
    • API clients must send the token back or turn the option off, as with CSRF. A PATCH-style partial submit that leaves out a field changed meanwhile is fine: it doesn’t overwrite it.

    The controller must only save when isValid() is true. A form in conflict has still modified the object in memory, like any invalid form.

    In the box

    The awkward cases are handled.

    ⚡

    LiveComponent-safe

    A component submits on every keystroke, and the first version let a re-render quietly swap the token. A test in the demo caught it; the explicit acknowledgement fixed it.

    🙈

    Never discloses

    A field that doesn’t render its value, like a password, only says it changed, so the conflict never reveals what the form hides.

    🏷️

    Readable values

    A choice shows its label (“Tutorial”), not its value (“2”), with the field’s own translation domain. Messages come in English and French.

    🧺

    Collections

    Entries the user adds or removes are fine, while entries someone else added are reported on the collection.

    🤝

    Taking their value

    Typing in the value someone else saved overwrites nothing, so that field is no longer a conflict and there is no box to tick.

    🔎

    GET forms skipped

    Searches and filters change nothing and are reached by plain links, so they get no token.

    🧩

    Dependent fields

    Fields rebuilt from the submitted values in PRE_SUBMIT don’t raise false conflicts.

    ✅

    Tested

    PHPStan level 9 and PHPUnit, exploration tests showing why the rejected options fail, and the demo played in a real browser.

    Get started

    Three steps,
    no form to touch.

    The bundle is a prototype and isn’t on Packagist yet, so Composer installs it from GitHub.

    Require the package

    composer config repositories.lock-form vcs https://github.com/marilenaRM/lock-form
composer require lock-form/form-concurrency:dev-main

    Enable the bundle

    // config/bundles.php
return [
    // ...
    LockForm\FormConcurrency\FormConcurrencyBundle::class => ['all' => true],
];

    Every root form is now protected, except GET forms. Your edit action must load the record on every request, which find() or an argument resolver already does.

    Place the confirmation box (optional)

    form_end() renders it. To put it next to your submit button:

    {% if form._concurrency_token_acknowledged is defined %}
    {{ form_row(form._concurrency_token_acknowledged) }}
{% endif %}
    WhereOptionDefault
    formconcurrency_protectiontrue
    formconcurrency_field_name_concurrency_token
    config/packages/form_concurrency.yamlenabledtrue
    config/packages/form_concurrency.yamlfield_name_concurrency_token
    Outside a Symfony application 
    $factory = Forms::createFormFactoryBuilder()
    ->addExtension(new FormConcurrencyExtension($secret, $translator))
    ->getFormFactory();
